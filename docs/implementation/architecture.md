# Architecture

## Overview

`neural_net` is a minimal, from-scratch neural network library. The design mirrors PyTorch's module system at a small scale: everything is a `Module`, parameters are explicit `Parameter` objects, and forward/backward passes are written by hand rather than generated by an autograd engine.

---

## Core Abstractions

### Tensor

`nn/core/tensor.py`

The fundamental data container. Wraps a NumPy `float64` ndarray and optionally tracks a gradient array of the same shape.

```
Tensor
├── .Data       → np.ndarray (float64)
├── .Grad       → np.ndarray | None
├── .RequiresGrad → bool
└── .Shape      → tuple
```

A `Tensor` with `RequiresGrad=False` has `.Grad = None`. Gradient memory is only allocated when actually needed (i.e., for `Parameter`).

### Parameter

`nn/core/parameter.py`

A `Tensor` subclass that always has `RequiresGrad=True`. Represents a trainable weight or bias. Modules register their parameters explicitly via `AddParameter()`.

### Module

`nn/core/module.py`

Abstract base class for all layers and containers. Defines the contract every component must satisfy:

```python
class Module(ABC):
    def Forward(self, x: Tensor) -> Tensor: ...
    def Backward(self, dZ: np.ndarray) -> np.ndarray: ...
```

Internal state:
- `_Parameters: dict[str, Parameter]` — leaf parameters owned by this module
- `_Modules: dict[str, Module]` — registered child modules

The `.Parameters()` property walks `_Modules` recursively, so `model.Parameters()` on a `Sequential` returns every parameter in every layer.

## Layer Design

### Linear

`nn/layers/linear.py`

Implements a fully-connected layer: $Z = WX + B$.

- **Weights** initialized with He initialization: $W \sim \mathcal{N}(0, \sqrt{2/\text{in}})$
- **Bias** initialized to zeros
- **Forward** stores input $X$ for use in backward
- **Backward** computes $dW = dZ \cdot X^T$, $dB = \sum dZ$, and returns $dX = W^T \cdot dZ$ for upstream layers

Accumulates gradients into `W.Grad` and `B.Grad` — the caller is responsible for zeroing them before the next step.

### Sequential

`nn/layers/sequential.py`

A container that chains modules: `output = module_n(...module_2(module_1(input))...)`.

- **Forward**: passes input through each module in order
- **Backward**: reverses the list, passing the gradient back through each module

## Activation Design

All activations follow the same pattern:

1. **Forward**: compute and return output; store whatever is needed for the gradient
2. **Backward**: receive upstream gradient `dZ`, return `dZ * local_derivative`

| Activation | Stored | Gradient formula |
| ---------- | ------ | ---------------- |
| Sigmoid | output $a$ | $dZ \cdot a(1-a)$ |
| Tanh | output $a$ | $dZ \cdot (1 - a^2)$ |
| ReLU | input $x$ | $dZ \cdot \mathbf{1}[x > 0]$ |
| Softmax | output $a$ | $a \cdot (dZ - \sum(dZ \cdot a))$ |

Activations are stateful between `Forward` and `Backward` calls. Calling `Backward` before `Forward` raises a `RuntimeError`.

## Loss Design

`nn/losses/mse.py`

Loss functions are callable objects (implement `__call__` which delegates to `Forward`).

- **Forward**: computes scalar loss; stores predictions and targets
- **Backward**: returns the gradient of the loss with respect to the predictions — this is the initial `dZ` passed into the network's backward pass

MSE backward: $\frac{\partial L}{\partial \hat{y}} = \frac{2}{n}(\hat{y} - y)$

## Data Flow

```
Forward pass:
  x (Tensor)
  → Linear.Forward(x)       stores x; returns Z = WX + B (Tensor)
  → ReLU.Forward(Z)         stores Z; returns A = max(0, Z) (Tensor)
  → Linear.Forward(A)       stores A; returns Z2 = W2A + B2 (Tensor)
  → MSELoss(Z2, y)          stores Z2, y; returns scalar loss (Tensor)

Backward pass:
  dZ = loss.Backward()      returns 2/n * (pred - y)
  dZ = Linear.Backward(dZ)  accumulates dW2, dB2; returns dA
  dZ = ReLU.Backward(dZ)    returns dZ * mask
  dZ = Linear.Backward(dZ)  accumulates dW1, dB1; returns dX (unused)

Parameter update:
  for p in model.Parameters():
      p.Data -= lr * p.Grad
```

## Naming Conventions

The codebase uses `PascalCase` for methods and properties (`.Forward()`, `.Data`, `.RequiresGrad`) rather than Python's conventional `snake_case`. This is an intentional stylistic choice for this project.

---

## What Is Not Implemented

The following modules exist as stubs (empty docstrings, no logic):

- **Autograd engine** (`nn/autograd/`) — dynamic computation graph; all gradients are currently hand-coded per layer
- **Optimizers** (`nn/optim/`) — SGD, Momentum, Adam
- **Weight initializers** (`nn/init/`) — Xavier, He as standalone utilities
- **Data pipeline** (`nn/data/`) — Dataset, DataLoader, Transforms
- **Training loop** (`nn/training/`) — Trainer, Callbacks, Metrics
- **Additional losses** (`nn/losses/`) — CrossEntropy, BinaryCrossEntropy
